# Kiln generated-app rules

You are editing a standalone macOS Electron app generated by Kiln. Keep the project packageable and local-first.

## Architecture

- `src/main/` owns Electron and OS access.
- `src/preload/index.ts` is locked. Do not edit it.
- `src/renderer/` is the React UI and should contain almost all feature code.
- Extend OS behavior only in `src/main/bridge/custom.ts`, then expose it through the documented custom channel.
- `electron.vite.config.ts` and `electron-builder.yml` are locked. Never edit them.

The renderer has `contextIsolation: true`, `nodeIntegration: false`, and `sandbox: true`. Never enable Node in the renderer and never use Electron `remote`.

## Bridge API

Use `window.kiln` from renderer code:

```ts
await window.kiln.fs.readText(path)
await window.kiln.fs.writeText(path, contents)
const chosen = await window.kiln.fs.openFile([{ name: 'Text', extensions: ['txt'] }])
await window.kiln.store.get('key')
await window.kiln.store.set('key', value)
await window.kiln.notify.show({ title: 'Done', body: 'Finished processing.' })
await window.kiln.clipboard.writeText('copied')
await window.kiln.shell.openExternal('https://example.com')
```

Tray/menu bar behavior, global shortcuts, and custom OS calls live in `src/main/bridge/custom.ts`; follow the examples already in the bridge modules.

## Required workflow

- Do not edit locked files or `.kiln/`.
- Do not add packages unless a Kiln capability recipe explicitly allows the exact package.
- Install allowed packages with `npm install --save-exact`.
- Use Tailwind and the existing UI primitives. Keep a native macOS feel: system font, compact controls, system light/dark mode, and the existing hidden-inset title bar.
- Never use inline remote scripts, `eval`, or unsafe HTML.
- Finish every build turn by running `npm run typecheck && npm run lint` and fix every error.

Read the relevant recipe copied into the prompt before using media, databases, permissions, PDFs, spreadsheets, screenshots, menu bar behavior, or other system capabilities.
